# Luis Alejandro Jaramillo · Portfolio

Personal portfolio of Luis Alejandro Jaramillo, Engineering Lead in payments and fintech platforms.
Built with [Astro](https://astro.build) as a fully static, single-page site with no client framework.
Available in English (`/`) and Spanish (`/es/`).

## Getting started

Requires Node.js 22.22 or newer.

```bash
npm install
npm run dev
```

The dev server runs at `http://localhost:4321`.

| Command           | What it does                                            |
| :---------------- | :------------------------------------------------------ |
| `npm run dev`     | Start the local dev server                              |
| `npm run build`   | Build the static site into `dist/`                      |
| `npm run preview` | Serve the production build locally                      |
| `npm run check`   | Type-check `.astro` and `.ts` files with `astro check`  |
| `npm run icons`   | Regenerate PNG/ICO icons from `public/favicon.svg`      |

## Project structure

```text
public/
  _redirects             Netlify rule that serves the Spanish 404 under /es/
  files/                 Downloadable resume (PDF)
  favicon.svg            Source mark for every icon
  favicon.ico, *.png     Generated by `npm run icons`
  site.webmanifest       Installable app name and icons
scripts/
  generate-icons.mjs     Rasterizes the favicon with sharp
src/
  assets/images/         Images optimized at build time
  components/
    layout/              Header, footer, language switch, theme toggle
    pages/               Page bodies shared by every locale (home, 404)
    sections/            One component per page section
    seo/                 <head> metadata, social cards, JSON-LD
    ui/                  Small presentational primitives
  config/site.ts         Site name, theme colors, navigation section ids
  data/
    profile.ts           Content types and language-neutral facts (name, email, links)
    locales/en.ts        English copy
    locales/es.ts        Spanish copy
  i18n/
    config.ts            Supported locales and the default locale
    index.ts             Helpers: getContent, localizePath, stripLocale
  layouts/               Page shell shared by every route
  pages/                 Thin routes: index and 404, plus es/ for Spanish
  scripts/               Client-side behaviour (theme, header, reveal, copy)
  styles/global.css      Design tokens, reset and shared primitives
```

## Updating content

- **Text** (experience, skills, highlights, education, headings, buttons): edit the locale file for that language. Components read from it, so no markup changes are needed. See [Languages](#languages).
- **Name, email, social links**: edit `profile` in `src/data/profile.ts`. These are shared by every language.
- **Resume**: replace `public/files/luis-alejandro-jaramillo-resume.pdf`, keeping the file name.
- **Portrait**: replace `src/assets/images/portrait.jpg`. Astro generates responsive WebP versions on build.
- **Domain**: update `site` in `astro.config.mjs`. It drives canonical URLs, social cards and structured data.
- **Icon**: edit `public/favicon.svg`, then run `npm run icons`.

## Languages

The site uses [Astro i18n routing](https://docs.astro.build/en/guides/internationalization/). English is the default locale and is served at `/`; Spanish is served at `/es/`.

| Language | URL    | Edit this file           |
| :------- | :----- | :----------------------- |
| English  | `/`    | `src/data/locales/en.ts` |
| Spanish  | `/es/` | `src/data/locales/es.ts` |

- **Editing copy**: change the string in the locale file. Both files follow the `Content` type in `src/data/profile.ts`, so `npm run check` fails if a field is missing or misspelled in either language.
- **Adding a field**: add it to `Content`, then fill it in every locale file and read it in the component with `getContent(Astro.currentLocale)`.
- **Adding a navigation link**: add the section id to `navigation` in `src/config/site.ts`, then add its label under `nav` in every locale file.
- **Copy rules** (all languages): short, outcome-focused sentences; no em-dashes or en-dashes. In Spanish, job titles, certification names and common industry terms (pricing, roadmap, event-driven) stay in English, as they appear in Colombian job posts.
- **SEO**: each page sets `<html lang>`, `og:locale`, a canonical URL and `hreflang` alternates (plus `x-default` pointing to English) from the locale files. Nothing to update by hand.
- **Adding a language**: add its code to `src/i18n/config.ts`, create `src/data/locales/<code>.ts`, register it in `src/i18n/index.ts`, and add `src/pages/<code>/index.astro` and `404.astro` (copy the `es/` ones).

## Design notes

- **Theme**: light and dark modes from CSS custom properties in `global.css`. The OS preference is the default; the toggle stores an explicit choice in `localStorage`.
- **Typography**: Geist and Geist Mono, self-hosted through the Astro Fonts API.
- **Color**: neutral grays with a single emerald accent.
- **Shape**: pill-shaped controls, `1rem` radius surfaces.
- **Motion**: entrance and scroll-reveal transitions on `transform` and `opacity` only, driven by IntersectionObserver and fully disabled under `prefers-reduced-motion`.
- **Icons**: [Phosphor](https://phosphoricons.com) SVGs imported as Astro components.

## Deployment

`npm run build` outputs a static site in `dist/` that any static host can serve (Netlify, Vercel, Cloudflare Pages, GitHub Pages). `404.html` is generated for hosts that support custom error pages. On Netlify, `public/_redirects` also serves the Spanish not-found page for missing paths under `/es/`.
